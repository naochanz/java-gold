Q2 Stream / sorted vs min

次のうち、コンパイルエラーになるものはどれか（複数選択可）
A. Stream.of(1, 2, 3).sorted();
B. Stream.of("a", "b").min();
C. Stream.of("a", "b").min(Comparator.naturalOrder());
D. IntStream.of(1, 2, 3).min();
E. Stream.of(1, 2, 3).max(Comparator.reverseOrder());
解答・解説
正解: B のみ

Stream<T> の min() / max() は Comparator が必須。引数なしで呼ぶとコンパイルエラー。

メソッド引数なしComparator あり
Stream<T>.sorted()✅（Comparable要素のみ）✅
Stream<T>.min()❌ コンパイルエラー✅
Stream<T>.max()❌ コンパイルエラー✅
IntStream.sorted()✅❌（引数なし版のみ）
IntStream.min() / max()✅❌
メンタルモデル: sorted は引数なしOK（並べ替えはComparable前提でできる）、min/max は引数なしNG（オブジェクトは比較方法を渡さないと最小最大が決まらない）。

  3. 3 1
  4. 1 1

解答・解説
正解: B

Stream.of(int[]) は Stream<int[]>（配列1個入ったストリーム）。Arrays.stream(int[]) は IntStream（要素ごと展開）。

覚え方: プリミティブ配列 → Arrays.stream 一択。Stream.of(int[]) は要素1個の罠。

解答・解説
正解: B

synchronized (lock) { ... }

// ❌ 危険
private final Integer lock = 10;
synchronized (lock) { ... }

11. ジェネリクス・型消去

Q1 型の非変性

次のコードはコンパイルできるか？
List<String> strs = new ArrayList<>();
List<Object> objs = strs;
  1. コンパイル成功、何も問題ない
  2. コンパイルエラー（型パラメータは非変）
  3. コンパイル成功、実行時に ClassCastException
  4. 警告だけ出てコンパイル成功
解答・解説
正解: B

String は Object のサブタイプだが、List<String> は List<Object> のサブタイプでない（非変性）。

もし許されたら、objs.add(123) で Integer が入って strs.get(0) で ClassCastException になるので、Java はコンパイル時に弾く。

Q2 ? extends T で add

次のコードのうち、コンパイルエラーになるものは（複数選択可）？
List<? extends Number> list = new ArrayList<Integer>();

A. Number n = list.get(0);
B. Object o = list.get(0);
C. Integer i = list.get(0);
D. list.add(1);
E. list.add(null);
解答・解説
正解: C, D
  • A: ✅ 上限の Number として読める
  • B: ✅ Number のスーパー Object としても読める
  • C: ❌ 実体が何か分からないのでサブクラスとして取れない
  • D: ❌ 実体が何か分からないので何も add できない
  • E: ✅ null だけは例外的にOK
PECS: Producer Extends - 読み取り専用に近い動作。

Q3 ? super T で add/get

次のコードのうち、コンパイルエラーになるものは（複数選択可）？
List<? super Integer> list = new ArrayList<Number>();

A. list.add(1);
B. list.add(new Integer(2));
C. list.add(new Number());
D. Integer i = list.get(0);
E. Object o = list.get(0);
解答・解説
正解: C, D
  • A: ✅ Integer を add 可
  • B: ✅ Integer の子クラスのインスタンスも add 可
  • C: ❌ Number は Integer の スーパー、Integer のサブじゃないので add 不可
  • D: ❌ 実体が Number/Object かもしれないので Integer で取れない
  • E: ✅ Object としてだけ取れる
PECS: Consumer Super - 書き込み専用に近い動作。

Q4 PECS の判定

「Stream の各要素を List に追加するメソッド」の正しいシグネチャは？
A. void copyTo(Stream<? extends T> src, List<? extends T> dst)
B. void copyTo(Stream<? super T> src, List<? super T> dst)
C. void copyTo(Stream<? extends T> src, List<? super T> dst)
D. void copyTo(Stream<? super T> src, List<? extends T> dst)
解答・解説
正解: C
  • src は読む側（Producer） → ? extends T
  • dst は書く側（Consumer） → ? super T

これが PECS（Producer Extends, Consumer Super）の典型例。Collections.copy も同じシグネチャ：

public static <T> void copy(List<? super T> dest, List<? extends T> src)

Q5 型消去とインスタンス化

次のコードのうち、コンパイルエラーになるものは（複数選択可）？
class Box<T> {
    A. T value;
    B. T[] arr = new T[10];
    C. List<T> list = new ArrayList<T>();
    D. static T staticValue;
    E. void m(T t) { System.out.println(t); }
}
解答・解説
正解: B, D
  • A: ✅ インスタンスフィールドはOK
  • B: ❌ new T[10] は型消去で T が分からないため不可
  • C: ✅ new ArrayList<T>() はOK（内部的には raw だが）
  • D: ❌ static フィールドに型パラメータは使えない（インスタンスごとに違う型なので）
  • E: ✅ メソッドの引数はOK
型消去の制約: new T[] / static で T / instanceof T / catch<T> / オーバーロード衝突 など。

Q6 オーバーロード衝突

次のクラスはコンパイルできるか？
class Foo {
    void f(List<String> list) { }
    void f(List<Integer> list) { }
}
  1. コンパイル成功
  2. コンパイルエラー（型消去後に同じシグネチャになる）
  3. 警告だけ出てコンパイル成功
  4. 実行時に ClassCastException
解答・解説
正解: B

型消去後はどちらも void f(List list) になり、メソッドシグネチャが衝突する。だからコンパイルエラー。

Q7 instanceof と型パラメータ

次のコードのうち、コンパイルできるものは（複数選択可）？
Object obj = ...;

A. if (obj instanceof List) { }
B. if (obj instanceof List<String>) { }
C. if (obj instanceof List<?>) { }
D. if (obj instanceof ArrayList<Integer>) { }
解答・解説
正解: A, C
  • A: ✅ raw type は OK（警告は出る）
  • B: ❌ 型パラメータ付きは不可（型消去で実行時に判別できない）
  • C: ✅ ワイルドカード ? は OK
  • D: ❌ 型パラメータ付きは不可
本質: 実行時には型消去で List<String> と List<Integer> が区別できないので、具体的な型パラメータでの instanceof は不可。

Q8 raw type の挙動

次のコードを実行した結果は？
List<String> strs = new ArrayList<>();
strs.add("hello");
List raw = strs;
raw.add(123);
String s = strs.get(1);
  1. "hello" のみ表示
  2. コンパイルエラー（raw type は使用不可）
  3. 実行時に ClassCastException
  4. "123" が表示
解答・解説
正解: C

型消去で strs も raw も実行時は同じ List。raw 経由で Integer の 123 が入る（コンパイル時には警告のみ）。strs.get(1) で取り出すとき暗黙のキャストが入って ClassCastException。

教訓: raw type を使うと型安全性が壊れる。後方互換のために残ってるだけで、新規コードでは絶対に使わない。

Q9 境界のあるジェネリック型

次のメソッド宣言として正しいものは？
「T は Number のサブクラスかつ Comparable<T> を実装している」と制約したい

A. <T extends Number, Comparable<T>>
B. <T extends Number & Comparable<T>>
C. <T extends Number | Comparable<T>>
D. <T super Number & Comparable<T>>
解答・解説
正解: B

複数の境界を指定するときは & で連結。

<T extends Number & Comparable<T>>
  • クラスは最大1つ、インターフェースは複数可
  • クラスを書く場合は最初に書く
  • カンマじゃない、| でもない
  • 型パラメータの境界に super は使えない（extends のみ）

Q10 ワイルドカード unbounded

次のコードのうち、コンパイルエラーになるものは？
List<?> list = new ArrayList<String>();

A. int size = list.size();
B. Object o = list.get(0);
C. list.add("hello");
D. list.add(null);
E. boolean b = list.isEmpty();
解答・解説
正解: C

List<?>（unbounded ワイルドカード）は「型が何か不明」を意味する。

  • A, E: ✅ 型に依存しない操作（size, isEmpty）はOK
  • B: ✅ Object としてだけ取り出せる
  • C: ❌ 何の型を受け入れるか分からないので add 不可
